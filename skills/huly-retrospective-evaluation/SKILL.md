# 产品项目复盘评估

## 复盘框架

围绕原目标与版本链比较：预期、实际、差异、关键事件、用户与业务结果、决策质量、交付质量、有效做法、失效假设和未解决问题。

## 判断规则

- 使用当时可获得的信息评价决策，不用最终结果倒推“当时一定应该知道”。
- 区分系统性问题、流程问题、信息缺口、执行偏差和个体失误，避免无证据归责。
- 区分事实、参与者观点和推测；重要结论应关联证据和时间。
- 改进项必须包含 Owner、完成定义、目标时间、验证方式和进入的后续流程。
- 需要改变产品方向时，返回相应 Requirement、Priority、Product Design 或 PRD Gate，不覆盖旧批准记录。

## 输出

输出目标与结果对照、关键差异、事件时间线、做得好的部分、问题及根因证据、失效假设、未解决事项和改进行动表。明确哪些经验可复用，哪些仅适用于本项目。

未获明确授权时不写回或关闭历史任务。
