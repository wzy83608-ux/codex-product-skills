# 需求优先级评估与排序

## 通用原则

本 Skill 不依赖固定目录、专用脚本、正式版本链或其他 Skill。输入可以来自用户、表格、文档、工单系统、Huly 或其他需求池。资料不足时仍可给出 `PROVISIONAL` 建议，但不得把未知项猜成确定等级。

## 工作流程

1. 明确评估单条需求还是需求池；目录或分类节点不作为需求项。
2. 收集问题、用户、影响、证据、战略关联、时效性、风险、依赖、估算和比较对象。没有来源的数字与判断标为未知。
3. 阅读 [优先级评估方法](references/priority-method.md)，分别评估价值、交付条件和相对排序。
4. P0 只用于有充分证据的事故、合规、安全、资金、数据风险或硬性外部期限。
5. P1/P2/P3 应在可比较需求池中判断；缺少比较池时标记 `priorityConfidence=PROVISIONAL`。
6. 输出当前优先级、建议优先级、排序原因、证据、风险、依赖、信息缺口和置信度。

如用户明确要求正式版本记录，可读取 [入口与生命周期方法](references/entry-lifecycle.md) 并使用当前环境已有的持久化能力；没有持久化工具时交付普通文档或结构化数据，不阻止评估本身。
