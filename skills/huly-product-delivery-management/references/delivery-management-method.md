# 产品交付管理方法

只读取与当前任务对应的章节。

## 1. 会议纪要 / 决策

区分讨论、已确认决定、建议、反对意见和待确认问题。每条决定记录 Decision ID、决定内容、Decision Owner、依据、影响范围、生效时间、复查条件和关联版本。行动项记录 Owner、Due Date、完成定义、依赖和状态。

没有明确拍板人或仍有冲突时，输出 `DECISION_PENDING` 或 `DECISION_CONFLICT`，不得把多数意见写成最终决定。会后只形成拟写回内容；未获明确授权不修改 Huly。

## 2. 项目管理

以已批准 Scope 和版本链建立项目视图，包含目标、In/Out Scope、里程碑、Workstream、Owner、依赖、风险、假设、变更和关键 Gate。研发 Estimate 和技术依赖仍由专业 Owner 提供。

范围变化必须说明来源、影响、是否需要返回 Requirement/Priority/Product Design/PRD，以及旧批准是否失效。不得把临时请求直接塞入当前范围。

## 3. 进度监控

状态只使用 `NOT_STARTED / IN_PROGRESS / BLOCKED / AT_RISK / DONE / UNKNOWN`。依据优先为已完成产物、当前有效 Gate、Issue 状态、依赖和最近证据。

输出计划与实际差异、阻塞时长、关键路径、下一个里程碑、需要升级的问题和恢复计划。百分比只有在工作拆分及权重有明确规则时使用；否则采用阶段和可验证交付物。

## 4. 测试质量

PM 关注验收标准覆盖、核心用户流程、P0/P1 缺陷、关键异常、权限、数据正确性、兼容范围、回归影响、未测范围和残余风险。

结果使用 `QUALITY_READY / QUALITY_AT_RISK / QUALITY_NOT_READY / UNKNOWN`。`QUALITY_READY` 必须引用 QA 或验收证据；本 Skill 不执行测试，也不替 QA 声明通过。PM 接受残余风险时记录影响、Owner、缓解措施和明确 Waiver。

## 5. 发布运维

从产品管理视角检查发布范围、目标版本、Feature Flag、灰度人群、迁移、兼容、回滚条件、监控指标、告警、客服/运营说明、值守、故障入口和发布后观察期。

结果使用 `RELEASE_READY / RELEASE_AT_RISK / RELEASE_NOT_READY / UNKNOWN`，但不执行部署、配置、数据库、回滚或生产写操作。实际发布状态必须来自发布系统或责任 Owner，不能由计划日期推断。

## 6. 数据分析

先写清产品问题、指标定义、口径、时间范围、分群、数据来源和新鲜度，再描述观察。区分相关性、推测和因果；没有实验或可靠识别策略时不得声称因果。

输出关键变化、可能解释、反证、业务影响、数据限制和建议决策。不得补造基线、目标值、样本量或统计显著性。若 PRD 使用 `METRIC_WAIVED`，保留该决定及原因。

## 7. 复盘评估

围绕原目标与版本链比较预期、实际、差异、关键事件、有效做法、失效假设、决策质量、交付质量、用户/业务结果和未解决问题。

行动项必须具体、可归属、可验证，并说明进入哪个后续流程。区分系统性改进与个体失误，避免用结果倒推当时一定应该知道的信息。需要调整方向时返回相应 Requirement、Priority、Product Design 或 PRD Gate，不直接改旧记录。

## 组合式项目周报

用户需要周报或综合项目状态时，合并为一张表，而不是重复七个模块：

| 区域 | 内容 |
|---|---|
| 总体状态 | 当前阶段、健康度、结论和证据时间 |
| 本期进展 | 已完成且可验证的交付物 |
| 决策 | 新决定、待决定、冲突及 Owner |
| 计划偏差 | 里程碑、关键路径和影响 |
| 质量与发布 | 测试、残余风险、发布准备状态 |
| 数据 | 已观察指标与限制 |
| 风险与阻塞 | 严重度、Owner、解除条件 |
| 下一步 | 行动、Owner、时间、完成定义 |

健康度只能是 `ON_TRACK / AT_RISK / OFF_TRACK / UNKNOWN`，并给出判断依据。
