# PRD 视觉资产规则

## 产品流程图

当PRD需要表达两步以上流程、分支、状态变化、角色协作或三个以上组件关系时，使用 `$fireworks-tech-graph` 生成图，不用纯文字字符画代替。

1. 只从已确认流程、规则、状态、角色和异常中提取节点与连线；证据不足的步骤不得补画。
2. 按流程图工具的完整规范生成并校验SVG，导出PNG，并执行视觉检查。PNG必须作为可见图片直接贴在PRD正文中；SVG仅作为可编辑源文件保留。
3. 将PNG和SVG放在PRD所在目录的 `assets/` 子目录，或用户明确指定的本地输出目录。文件名使用稳定、可读的英文小写短横线格式。
4. 在PRD“产品流程图”标题下立即插入内嵌图片语法，使阅读PRD时直接看到流程图，而不是点击链接后查看。例如：

   ```markdown
   ![产品流程图](C:/absolute/path/to/prd/assets/product-flow.png)

   [查看或编辑SVG源文件](C:/absolute/path/to/prd/assets/product-flow.svg)
   ```

5. 路径包含空格时使用尖括号包住链接目标。不得使用相对路径、`file://`、不存在的路径或临时目录路径。
6. Markdown或本地文档交付时，确认渲染结果中图片实际显示；只显示路径文字、破图标记或下载链接均不算完成。
7. 写入Huly、在线文档或其他远程载体时，必须将PNG上传为文档图片资源，并在“产品流程图”正文位置插入图片节点。不得用本地路径、附件链接或SVG链接替代正文图片；目标系统不支持图片上传时明确报告阻塞，不宣称已经贴图。
8. 交付前验证PNG和SVG都存在，PNG能够打开且视觉检查通过。流程与正文发生变化时重新生成图，避免图文不一致。

流程信息不足时，不生成推测性图片；省略该模块或列出缺失步骤、所需依据和确认Owner。

## 交互原型图

“交互原型图”必须提供可以实际打开的本地文件地址，通常是HTML入口、图片、PDF或其他本地原型文件。

1. 输出前验证文件存在，并解析为绝对路径。
2. 使用Markdown本地文件链接，例如：

   ```markdown
   [查看交互原型](C:/absolute/path/to/prototype/index.html)
   ```

3. 路径包含空格时使用尖括号包住链接目标。不得写空链接、示例Figma地址、虚构地址或仅有目录而没有入口文件的地址。
4. 多个原型按模块列出名称、绝对本地地址、对应功能和版本或更新时间。
5. 若只有在线原型，可在附录保留其真实在线链接，但不能把在线链接冒充本地地址。用户要求本地地址而文件尚未落地时，将“本地原型文件缺失”列为待补充项，不生成假的路径。

本地路径通常只在生成PRD的计算机上有效；写入Huly等远程系统时仍按用户要求保留路径，同时明确其他设备可能无法访问。
