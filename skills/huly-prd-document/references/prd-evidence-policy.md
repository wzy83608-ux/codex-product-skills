# PRD 证据与引用规则

## 证据账本

写作前建立证据账本，每条依据分配 `E01`、`E02` 等ID，记录：依据类型、来源标题、来源主体、日期、链接或内部文档ID、可支持的结论、适用范围和限制。

允许的依据类型：

- `FACT`：用户直接输入、用户反馈、访谈、行为数据、工单、会议已确认决定或其他原始事实。
- `INTERNET`：可访问的公开网页、官方文档、法规、标准、研究或可信机构资料。涉及当前产品、市场、法规、版本或行业现状时必须实际检索核验，给出标题、链接和检索日期。
- `HISTORICAL_PRODUCT`：当前或过往产品PRD、Huly文档、版本记录、原型、产品规则、上线记录或复盘资料。必须标明版本、状态和日期，历史设计不能自动证明当前已经上线。
- `BUSINESS_KNOWLEDGE`：经业务Owner确认的规则、流程、约束或术语。必须记录确认人或责任角色、确认日期及来源记录；未经确认的业务经验只能标为待确认。
- `INDUSTRY_KNOWLEDGE`：行业标准、权威机构材料、公开研究或有明确出处的行业惯例。必须可核验；模型自身记忆或“通常如此”不算依据。

## 使用规则

1. 每个确定性的范围、规则、流程、状态、异常、权限、指标、价值判断和验收结果都必须能追溯到至少一条证据。
2. 来源只能支持其明确覆盖的内容，不得从“资料存在”推导“功能已上线”，也不得从相关性推导因果。
3. 多来源冲突时并列记录冲突，不代替Owner选择答案。
4. 公开资料只能补充行业背景、规范或对比，不得覆盖用户已经确认的业务事实。
5. 需要互联网或行业资料但当前无法核验时，省略相关模块或列为待确认，不使用记忆补写。
6. 不得编造用户数量、频率、收益、转化率、工期、目标值、竞品能力、法规要求或技术限制。

## 证据不足时

- 不影响其他已确认内容：省略对应模块或条目，并在交付说明中列出未写原因。
- 会改变范围、业务规则、权限、核心流程或验收结果：停止生成受影响部分，输出阻塞问题、所需证据和确认Owner。
- 可以合理推演但尚未确认：不得写入正式PRD正文；可放入“待确认事项”，明确标记为 `HYPOTHESIS`。
