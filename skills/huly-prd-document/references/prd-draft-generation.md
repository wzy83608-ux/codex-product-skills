# PRD 草稿生成规则

## Gate

正式流程模式只允许使用最新且仍有效的 `PRD_READY` 记录生成，并重新验证当前上游版本链和审批指纹。独立草稿模式使用用户提供的证据包和当前检索到的可核验资料，不伪造正式流程状态。

## 转写边界

只允许整理、归纳、去重、统一表达、章节化、编号和建立交叉引用。不得新增功能、改变 Selected Solution、改变流程或规则含义、新增状态/权限/异常、创造成功指标、技术实现或工期。每项确定内容必须关联证据ID；缺少信息时省略无依据模块，或记录“信息不足”、缺失来源、Blocking 属性、Owner 和建议动作。

## 草稿与校验

按 [PRD 输出格式](prd-structure.md) 生成Markdown；有持久化要求时可同时生成结构化记录。章节按适用性选择，不要求空模块齐全。保留Section与Item两级来源溯源，并在适用时建立 `功能 ↔ 规则 ↔ 状态/异常 ↔ 验收标准` 映射。轻量校验只允许修正文档结构；发现业务内容或证据问题必须返回上游或标记待确认。

若正文包含“产品流程图”，按 [PRD视觉资产规则](prd-visual-assets.md) 调用流程图工具生成、校验和视觉检查PNG/SVG，再把PNG以内嵌图片形式直接插入PRD对应正文位置，并保留SVG源文件地址。远程文档必须上传PNG并插入图片节点，不能只写路径或附件链接。若包含“交互原型图”，必须在写入前验证本地入口文件存在并使用绝对路径；不存在时不得创建示例或虚构链接。

草稿状态固定为：`PRD 草稿已生成`、`prdDraftGenerated=true`、`prdReviewed=false`、`prdApproved=false`、`developmentEntryEligible=false`，下一步只能是 PRD Reviewer。

上游任何版本或审批指纹变化后，旧草稿保留但有效状态变为“PRD 草稿已失效”，必须重新执行 Readiness 并生成新版本。
