# PRD 需求文档生成与审查

## 通用原则

本 Skill 不依赖固定目录、专用脚本、本地记录库、特定版本编号或其他 Skill。输入可以是产品设计、会议决定、原型、需求分析、用户资料或 Huly 证据。缺失正式版本链时仍可生成 `STANDALONE_DRAFT`，但必须列明假设、未知项和待确认 Owner。

## 工作流程

1. 阅读 [PRD 就绪检查方法](references/prd-readiness-method.md)，判断现有输入是否足以成文；真正影响范围、规则、权限或验收的缺口应阻塞。
2. 阅读 [PRD 标准结构](references/prd-structure.md)，建立章节和来源映射。
3. 生成正文时读取 [PRD 草稿生成规则](references/prd-draft-generation.md)，确保目标、范围、流程、状态、异常、数据、权限、指标和验收标准可追溯。
4. 审查时读取 [PRD Reviewer](references/prd-reviewer.md)，区分安全的编辑修正与需要业务 Owner 决定的问题。
5. 需要人工确认或最终审批时，读取对应参考方法；没有记录系统时以带日期、Owner 和版本标识的普通文档记录，不伪造正式 Gate 状态。

## 边界

不重新分析需求，不替用户选择产品方案，不改变已确认范围，不编写技术架构或开发任务，不声明开发已经获准，也不自动写回任何外部系统。
